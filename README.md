# Law Links Service

Командное ДЗ №1 по курсу генеративных моделей / анализа текста (ФТиАД, ВШЭ).

Сервис находит в тексте юридические ссылки и возвращает их в виде структуры
`{law_id, article, point_article, subpoint_article}`. Каждая комбинация разворачивается
в отдельную ссылку: `пп. 1, 2 п. 3 ст. 4 НК РФ` → две ссылки.

## Запуск

Сборка и запуск одинаковые на Linux, macOS и Windows (нужен запущенный Docker; на Linux при необходимости с `sudo`):

```bash
docker build -t law-links-service .
docker run -d -p 8978:8978 --name law-links-container law-links-service
```

Проще всего проверить сервис через Swagger: http://localhost:8978/docs → `POST /detect` → «Try it out». Проверка живости: `GET /health`.

**Запрос из терминала — Linux / macOS:**
```bash
curl -X POST "http://localhost:8978/detect" \
     -H "Content-Type: application/json" \
     -d '{"text": "Согласно пп. 1 п. 1 ст. 374 НК РФ и ст. 151 настоящего Кодекса"}'
```

**Запрос из терминала — Windows (PowerShell):**
```powershell
$body = @{ text = "Согласно пп. 1 п. 1 ст. 374 НК РФ и ст. 151 настоящего Кодекса" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:8978/detect" -Method Post `
    -ContentType "application/json; charset=utf-8" `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) | ConvertTo-Json -Depth 5
```
(`curl` в PowerShell — это другая команда, и кириллица в ней ломается, поэтому `Invoke-RestMethod`.)

Ожидаемый ответ:
```json
{"links": [
  {"law_id": 15, "article": "374", "point_article": "1", "subpoint_article": "1"},
  {"law_id": 15, "article": "151", "point_article": null, "subpoint_article": null}
]}
```

Остановить: `docker rm -f law-links-container`.

**Без Docker** (Python 3.10+):
```bash
python -m pip install -r requirements.txt               # Windows: py -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8978   # Windows: py -m uvicorn app.main:app --host 0.0.0.0 --port 8978
```

Если Docker не может скачать базовый образ (`connection reset by peer`), можно взять его из зеркала:
```bash
docker pull mirror.gcr.io/library/python:3.12-slim
docker tag mirror.gcr.io/library/python:3.12-slim python:3.12-slim
```
после чего собрать образ как обычно.

## Как устроено

Решение полностью на правилах и словарях, без нейросетей: по условию проверка идёт на слабой машине с лимитом 5 минут на 2000 текстов. Единственная внешняя зависимость сверх шаблона — `snowballstemmer` (стемминг для склонений).

```
text ─┬─► laws.find_laws   ──► где в тексте какие законы      [(start, end, law_id)]
      └─► refs.find_refs   ──► где какие ст./ч./п./пп.         [(start, end, статьи, пункты, подпункты)]
                   │
                   ▼
            linker.link    ──► какая ссылка к какому закону ──► [LawLink]
```

**1. Распознавание закона — `app/laws.py`**
- Нормализация без сдвига позиций: латиница-двойник → кириллица (`HК` → `НК`), `ё` → `е`, `Ф3` → `ФЗ`, нижний регистр.
- Стемминг (Snowball): «Налогового кодекса» совпадает с «Налоговый кодекс». «РФ / России / Российской Федерации» сводятся к одному токену.
- Trie по всем ~18,7 тыс. алиасам из `law_aliases.json`, приоритет у самого длинного совпадения. Добавлены сокращения, которых нет в базе: КоАП, КРФоАП, ГрК, КАС.
- Разбор «шапки» акта: вид + номер + дата + название в любом порядке. Так снимается неоднозначность номеров: «№ 127-ФЗ» в базе соответствует 5 разным законам.
- Нечёткий поиск для опечаток («Налогвого», «Президена»), сокращённые названия («Закон о банкротстве»), определения в тексте («далее — Закон о связи»).
- Отсев ложных срабатываний: «Заказ № 127-ФЗ», «ЖК «Речной»», номер или дата, противоречащие базе.

**2. Парсер структуры — `app/refs.py`**
- Маркеры `ст.`, `ч.`, `п.`, `пп.` и их полные формы во всех падежах, плюс опечатки («стаья», «пунта»).
- Перечисления («ст. 15, 1064», «ст.ст. 303, 304», «пп. «а, в, г»») и диапазоны («ст. 307-309», «390.14-390.16», «пп. а-в»). Диапазоны разворачиваются в отдельные ссылки.
- Иерархия любой глубины и порядка: «пп. 1 п. 2 ст. 3», «статья 5 пункт 3», «часть первая статьи 12».
- Часть (`ч.`) записывается в `point_article`, как и пункт. Если в ссылке есть и часть, и пункт («п. 1 ч. 1 ст. 24»), то часть → `point_article`, пункт → `subpoint_article`.

**3. Связывание — `app/linker.py`**
- Ссылка получает закон справа, если между ними только «связки»: другие номера, запятые, «и», «и др.» («ст. 389.15, 389.18, … 389.35 УПК РФ»).
- Анафоры: «ст. 151 настоящего Кодекса», «указанного Закона», «статьей 139 Кодекса» → последний упомянутый закон того же вида (кодекс или закон).
- Сомнительные ссылки отбрасываются: метрика — accuracy по текстам, и одна лишняя ссылка обнуляет весь текст.

## Результаты

Наш eval-набор: 555 текстов (реальные судебные акты с sudact.ru, документы ПБУ/ФСБУ, синтетика), разбитых по сложности так же, как бенчи. Отдельно 67 «ловушек»: тексты без ссылок, которые выглядят похоже («т. 1, л.д. 95-98», «войсковая часть 25522», пункты договоров).

| Набор | Текстов | Accuracy | Accuracy с шумом* |
|---|---|---|---|
| level1: одна статья | 114 | 0.991 | 0.974 |
| level2: статья + часть/пункт | 180 | 0.967 | 0.944 |
| level3: несколько ссылок, перечисления, диапазоны | 169 | 0.994 | 0.964 |
| level4: анафоры, кривые номера, дата словами | 25 | 0.840 | 0.800 |
| ловушки | 67 | 1.000 | 1.000 |

\* `scripts/make_noisy.py`: латиница вместо кириллицы, ВЕРХНИЙ/нижний регистр, лишние и пропавшие пробелы, переносы строк, опечатки в словах-маркерах.

Accuracy считается по текстам: текст засчитан, только если набор ссылок совпал с эталоном целиком. Для сравнения: бейзлайн на закрытых бенчах — 0.49 / 0.35 / 0.14 / 0.07. Наши наборы с бенчами не совпадают, поэтому цифры напрямую несравнимы.

**Скорость:** 2000 HTTP-запросов за ~5 с на одном процессе (лимит — 300 с), ~1–2 мс на текст, старт сервиса ~1–2 с (загрузка индекса законов).

## Принятые решения (по ответам преподавателя)

- **Метрика — accuracy.** Поэтому точность важнее полноты: сомнительную ссылку лучше не вернуть.
- **Все законы из бенчей есть в `law_aliases.json`.** Если закон не нашёлся, ссылка отбрасывается, `law_id = null` не возвращаем.
- **Диапазоны разворачиваются:** «43.2-6» → 43.2, 43.3, 43.4, 43.5, 43.6.
- **Ресурсы минимальные**, отсюда правила вместо моделей.
